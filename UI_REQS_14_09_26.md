### 2. Detailed Functional Requirements

#### A. Input & Auto-Suggestion Drawer

- **FR-SRC-1.1 (Focus / Zero-Query State):** When the user focuses on the search input without typing, the system shall display a dropdown menu titled `Trending` containing top system-wide query strings (e.g., `articulation`, `sql course`, `claude certified architect`).
- **FR-SRC-1.2 (Real-Time Categorized Suggestions):** When the query string length $\ge 1$, the system shall debounce input by 200ms and execute dynamic multi-category lookup:
  - **Search Suggestions:** List matching search phrases formatted in plain text.
  - **Courses Group:** Render maximum 3 mini course cards featuring thumbnail image, full title, and sub-metadata (`Course • Author Name`).
  - **Instructors Group:** Render matching instructor profile items with round avatar thumbnails, display name, and instructor credential subtitle.

#### B. Search Results Execution & AI Overview Spotlight

- **FR-SRC-2.1 (Search Page Route):** Submitting a search query shall route the user to `/courses/search/?q={url_encoded_query}`.
- **FR-SRC-2.2 (AI Overview Card):** The system shall analyze the query intent and render an inline summary block featuring:
  - Section title: `AI Overview`.
  - Explanatory intent statement (e.g., _"This topic is best learned start to finish — here is our top pick..."_).
  - Prominent featured course recommendation card containing title, badge (`Bestseller`), rating score, lecture count, target skill level, and a `View course` CTA.

- **FR-SRC-2.3 (Course Hover Popover):** Hovering over any course card in the search grid shall open a detailed flyout card displaying key learning outcomes (`What you'll learn` checklist), total content hours, lecture breakdown, and direct `Add to cart` action buttons.

#### C. Faceted Filter Engine & Quick Filter Controls

- **FR-SRC-3.1 (Filter Side Drawer Capabilities):** The system shall provide a slide-out filter panel supporting multi-select criteria, updating dynamic item counts for each filter option:
  - **Certification Toggle:** Switch toggle for `View certification prep courses only`.
  - **Ratings Filter:** Radio choices for minimum average rating (`4.5 & up`, `4.0 & up`, `3.5 & up`, `3.0 & up`).
  - **Language Filter:** Checkboxes for multi-language selections (e.g., `English`, `Español`, `Português`, `日本語`).
  - **Hands-on Practice Filter:** Checkboxes for content features (`Quizzes`, `Coding Exercises`, `Practice Tests`, `Role Plays`).
  - **Video Duration Filter:** Segmented ranges (`0–1 Hour`, `1–3 Hours`, `3–6 Hours`, `6–17 Hours`, `17+ Hours`).
  - **Topic Filter:** Nested tags (e.g., `Python`, `SQL`, `Java`, `Object-Oriented Programming (OOP)`).
  - **Level Filter:** Target difficulty level (`Beginner`, `Intermediate`, `All Levels`).
  - **Subtitles & Price:** Captions presence (`English`, `Français`) and pricing model (`Paid`, `Free`).

- **FR-SRC-3.2 — Quick-Filter Bar & Active Filter Pills:** The course discovery page shall provide a responsive quick-filter bar positioned above the course results grid. The bar shall expose commonly used filters such as Hands-on Practice/Content Type, Language, Ratings, Level, and other high-frequency discovery parameters.

  All quick filters and the full All Filters interface shall operate on a single centralized filter state. Selecting a filter from either interface shall immediately synchronize the other interface and asynchronously update the course results without a full-page reload.

  Every currently active filter value shall be represented above the course grid as an individual dismissible filter pill/chip. Each pill shall display the human-readable filter value and provide an X control that removes only that specific filter value while preserving all other active filters.

  Checkbox-based filter groups shall support multi-selection, with values within the same filter group treated as OR conditions and different filter groups combined using AND semantics. Radio-based filters such as minimum rating shall permit only one active value at a time. Toggle filters shall maintain an explicit boolean state.

  The interface shall provide a Clear all action whenever one or more filters are active. Clearing an individual pill shall immediately update the centralized filter state, URL/query parameters, result count, and course grid.

  Filter state should be synchronized with URL query parameters so that filtered course results can be refreshed, bookmarked, shared, and navigated using browser Back/Forward controls.

  The filtered result count shall be displayed alongside the course results and updated whenever the filter state changes. If the active filter combination produces no results, the system shall display a dedicated empty state with an action to clear the active filters.

  On mobile and narrow viewports, the quick-filter controls and active filter pills shall remain usable through horizontal scrolling or an equivalent responsive interaction without causing layout overflow.

  **Acceptance Criteria:**

  - Selecting English creates an `[ English × ]` active filter pill.
  - Selecting 4.5 & up creates a `[ 4.5 & up × ]` pill while preserving English.
  - Clicking the X on `[ English × ]` removes only the English filter.
  - Selecting multiple languages creates separate active pills for each selected language.
  - Selecting a different rating replaces the existing rating filter.
  - The All Filters panel and quick-filter bar always reflect the same filter state.
  - Applying/removing filters updates course results asynchronously without a full page reload.
  - The filtered result count updates with the query results.
  - Clear all removes every active filter and restores the default course listing.
  - Refreshing a filtered URL preserves the active filter state.
  - Browser Back/Forward navigation restores the corresponding filter state.
  - Zero-result combinations display a meaningful empty state rather than a blank grid.
  - Filter interactions remain usable on mobile/narrow screens.
  - Filter counts displayed in the filter panel accurately represent the backend-provided result counts and are not hardcoded.
- **FR-SRC-3.3 (Sorting Engine):** Provide a dropdown menu sorting the results by `Most Relevant` (default), `Highest Rated`, `Most Reviewed`, and `Newest`.

#### D. Discovery & Recommendation Footer

- **FR-SRC-4.1 (Related Searches Section):** System shall evaluate search query vectors and render a list of related search query chips at the bottom of the page (e.g., `claude code - the practical guide`, `ccaf`, `claude agents`, `claude code masterclass`).
- **FR-SRC-4.2 (Hot and Fresh Carousel):** System shall populate a horizontal scrollable course shelf highlighting newly released courses relevant to the query topic.
